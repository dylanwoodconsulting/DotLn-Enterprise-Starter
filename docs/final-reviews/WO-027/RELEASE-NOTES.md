## Release overview

This patch changes the workspace's tools and reference documents so that they say and check what is so. The board count CI prints now counts a boarded defect wherever it sits, the script-reference check fails on a missing or stale row, pull-request titles with a gitmoji and a subject stay as written, and the references match the registered gate, the feature barrel shape, the Angular cache setting, the filed records and the scene's performance coverage. A colleague or a coding session reading DotLn-Angular gets instructions and gauges that agree with the repository. Nothing in the app changes.

## Read before upgrading

Nothing to do in the app. No application code, route, library, runtime dependency, stored data or translation changes, so the app behaves as `DotLn Angular v0.10.0` does. Two gauges now refuse what they used to pass: `npm run boards` counts markers in `tools/` and `.github/` and reports 1 at this release, and `npm run check:scripts` fails when the scripts reference lacks a row for an npm script or a direct module, or names one that does not exist. A pull-request title may now carry a supported gitmoji and a subject with no conventional type; a conventional title still gains its gitmoji and a bare subject is still refused.

## Substantive changes

- **The board gauge.** `tools/board-count.mjs` visits every tracked script, Sass, HTML and YAML file outside `docs/` and `node_modules`, reads comments through the TypeScript parser or a lexical scan for each syntax, and counts a line whose first non-blank text is the comment token followed by `BOARDED:`, once per line; strings, inline mentions and JSON do not count. Its tests cover each syntax, multiline strings, raw-text HTML elements, YAML block scalars and flow maps, and the tracked-file scope. The fork pull-request title limitation is boarded beside its failing edit and is the one marker counted.
- **The script reference check.** `tools/scripts/check-script-reference.mjs` reads the reference's tables outside fenced code, requires a row for every npm script and every `.mjs` file directly under `tools/scripts`, and refuses a row naming a script or module that does not exist. Its test runs the real command on a scratch copy with the unmodified reference, with the `npm run boards` row removed and with a row for a script that does not exist.
- **The title workflow.** `tools/pr-title.mjs` leaves a title that opens with a supported gitmoji, shortcode or emoji, and a subject as written, decorates a conventional title with its type's gitmoji and refuses a bare subject; the tests cover the three forms and the workflow's no-op on an already valid title.
- **The command lists.** The sub-app rules list the registered gate's plain tier once, in order, with the e2e type check, and name the review tier for a change that adds a route or a page; the root README and both reference indexes say `npm run lint` includes `npm run test:tooling` and that CI runs the affected projects' targets.
- **The conventions and rules.** A feature library exports only its routes from `index.ts`, directly or through a `public_api.ts` that names only those routes. `nx.json` disables the Angular CLI cache because a linked worktree would share the base checkout's cache; the cost is no dev-server prebundling and a warning per serve, and the choice reopens when Angular offers a portable worktree-local cache or rebuild time becomes a concern. Rules 20, 21 and 26 and the scripts reference describe the three tools as they now behave.
- **The catalog, the records and the scene.** The catalog states the study doctrine inline, names the launchpad repository with a pinned link to its design records and drops the dates of design rounds. The developer reference's `docs/dotln` row says the filed records' links resolve from their original paths in the launchpad at the final review's checkpoint, which may exist only locally. The performance guide says `perf:sample` covers the catalog journeys and not the scene, gives the scene's structural bound of one signal write per frame, and says scene sampling is added when an observed concern needs measurement.

## Progressive polish

The developer reference's path table was reformatted by Prettier after its `docs/dotln` row grew; the rendered table is unchanged. The board gauge and the script-reference check keep their pass line and count format, and the `boards` and `check:scripts` rows in the scripts reference say what each now does.
