# Make the gate tools and reference documents say and check what is so

## Summary

A coding session that opens the AI reference's sub-app rules now runs the registered gate's plain tier as the launchpad registers it, with the e2e type check and no command twice. The operator reads a board count in CI that counts a `BOARDED:` marker wherever the defect sits, in `tools/` or `.github/` as in `libs/`; on this change it is 1, the fork pull-request title limitation, boarded beside its failing edit. A colleague who removes a row from the scripts reference, or adds one for a script that does not exist, sees `npm run check:scripts` fail. A pull request titled with a gitmoji and a subject, like this one, keeps its title. The documents explain the feature barrel exception, why the Angular CLI cache is off and what it costs, where the filed records' links resolve, the study doctrine inline, and what the performance policy says about the scene the root opens.

- **The board gauge** (`tools/board-count.mjs`) visits every tracked script, Sass, HTML and YAML file outside `docs/` and `node_modules`, reads comments through the TypeScript parser or a lexical scan for each syntax, and counts a line whose first non-blank text is the comment token followed by `BOARDED:`, once per line. Strings, inline mentions and JSON do not count. Its tests cover each syntax, multiline strings, raw-text HTML elements, YAML block scalars and flow maps, and the tracked-file scope.
- **The script reference check** (`tools/scripts/check-script-reference.mjs`) reads the reference's tables outside fenced code, requires a row for every npm script and every `.mjs` file directly under `tools/scripts`, and refuses a row naming a script or module that does not exist. Its test runs the real command on a scratch copy: the unmodified copy passes, the copy without the `npm run boards` row fails even when prose still names it, and a row for `npm run removed:check` fails.
- **The title workflow** (`tools/pr-title.mjs`) leaves a title that opens with a supported gitmoji, shortcode or emoji, and a subject as written; a conventional title still gains its type's gitmoji; a bare subject is still refused. The draft of this pull request was the live test: the workflow ran on its gitmoji-and-subject title and left it unchanged.
- **The documents.** The sub-app rules list the plain tier (`npm ci`, `npx nx run-many -t lint`, `npm run typecheck:e2e`, `npx nx run-many -t test`, `npx nx format:check`) and the review tier for a change that adds a route or a page. The three READMEs say `npm run lint` includes `npm run test:tooling` and that CI runs the affected projects' targets. Conventions rule 4 and the foundation rules say a feature library exports only its routes from `index.ts`, directly or through a `public_api.ts` that names only those routes, which the six feature barrels match. Rule 2 says `nx.json` disables the Angular CLI cache because a linked worktree would share the base checkout's cache, that this costs dev-server prebundling and a warning per serve, and when to reopen it. The catalog states the study doctrine inline, names the launchpad repository with a pinned link to its design records, and drops the dates of design rounds. The developer reference's `docs/dotln` row says the filed records' links resolve from their original paths in the launchpad at the final review's checkpoint, which may exist only locally. The performance guide says `perf:sample` covers the catalog journeys and not the scene, gives the scene's structural bound and says when sampling is added. Rules 20, 21 and 26 and the scripts reference describe the three tools as they now behave.

Application code, libraries, runtime dependencies and the filed records under `docs/dotln/` are unchanged, and `package.json`'s dependency keys equal the base's.

## Validation

The declared review gate (install, lint, e2e type check, unit tests, format, build, e2e and visual) passed at the reviewed tree with no tracked-byte mutation. Its lint and visual commands ran; test, build and e2e replayed Nx's cache of the runs at the earlier trees, whose project inputs this change does not touch. `node --test tools/` passes 92 tests, naming the five controls above. On scratch copies, `node tools/board-count.mjs` printed 1 on the candidate, 3 with a marker appended to `tools/pr-title.mjs` and to `.github/workflows/ci.yml`, and 1 with a string holding the marker text appended. CI's `checks`, `visual` and `title` jobs passed on the draft's head from a clean checkout.

An independent verifier walked the session the change is for: ran the plain and review tiers from the sub-app rules alone and matched them to the registered gate, watched the board count move on a copy of a workflow, read the cache paragraph and found the behavior in the installed Angular build, followed every pointer in the catalog including the public design-record link, read the scene paragraph, and watched `check:scripts` refuse a removed row and a stale row. A first verification failed because two documents named a launchpad repository that does not exist; the repair named the repository as its remote and the launchpad's records do, and the second verification resolved the link anonymously.

## Review

The final review read the whole diff, reran the tooling tests, the board count, the script-reference check and the document probes at the reviewed tree, compared the six feature barrels and the dependency keys with the base, and read the draft pull request's workflow runs. It removed one file from the candidate: a release-notes file the execution had added at the repository root, which nothing in the repository or the release route reads, because the patch's reviewed notes live with the launchpad's final report and become the Release body at the tag. The review gate reran at the resulting tree and passed. No other byte of the verified tools or documents changed.

## Limits and follow-ups

None of these blocks the change, and each is recorded with its owner.

- The title workflow admits the eleven gitmoji in `.github/gitmoji-map.json`, while the launchpad's publish lint admits any gitmoji and a subject, so a title the launchpad admits can still fail here; a shared case list is the follow-up.
- The filed records' relative links resolve at a launchpad checkpoint that exists only locally, so a colleague reading both repositories on GitHub cannot follow the links that leave this repository; the `docs/dotln` row says so, and how the checkpoints become public is a launchpad decision.
- A marker inside a workflow's `run: |` block is part of a YAML string, not a comment, so a workflow defect is boarded with a comment beside its step.
