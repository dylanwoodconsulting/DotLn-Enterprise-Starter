## Release overview

This minor release gives Enterprise Integration Patterns its first twenty concept studies, each a flow the reader steps message by message. A reader opens Tools or the catalog, sees the work counted as twenty studied, and under Aggregator, Publish-Subscribe Channel, Competing Consumers, Request-Reply and sixteen others reads one worked example from several sides: the idea and a situation it serves, a flow of endpoints and channels with a sentence naming what moves where at each step, ordinary pseudocode, an RxJS reading whose comments name the pattern's parts, public implementations, references, limits and the nearby patterns. It matters because the vocabulary of agents handing records through channels, and where each pattern fails, can be learned by stepping a drawing rather than reading a definition; where a pattern is a stream, the drawing is built from the very example a test ran.

## Read before upgrading

- **The study model gains a third family.** `StudyModel` is now `MotionStudyModel | MarblesStudyModel | FlowStudyModel`, and `StudyDrawingView` gains `FlowDrawingView` with its `flow` and `marbles` views. Code that narrows on `family` gains a `flow` case; moments are still read through `ticksOf`. These are internal to the Tools feature.
- **The record check is stricter for the messaging work.** `npm run studies:check` now refuses a `flow` drawing over an executable example that does not read the executable module, and in the `eip` work, as in `rxjs`, an RxJS reading either runs or begins with `// Illustrative:` and its reason.
- **`StudyScrubber` takes `counting`.** `'frame'` keeps the marble diagram's `Frame 5 of 14`; `'step'` names a flow's `Step 5 of 8`. `tools.study.flowView`, `tools.study.marblesView`, `tools.study.stepOf` and `tools.study.messages` are new translation keys.
- **The catalog layout's columns moved into a grid of their own.** The shelf, contents and reading sit in a `.columns` box inside `.catalog`, so a sticky shelf or contents list stops above the reading history; spacing at every width is unchanged, and the catalog's 1440 visual baseline was regenerated for the shelf's new studied line.
- **The studied count is sixty.** The search facet and the Tools home count the three studied works together.
- No dependency is added or changed. Node 26 and npm as before. A branch that publishes after this one integrates `main` and rewrites `studies-summary.json` with `npm run studies:check -- --write-summary`.

## Substantive changes

- **The catalog reading surface.** Twenty studied concepts in Enterprise Integration Patterns, each at its own address: Aggregator, Publish-Subscribe Channel, Correlation Identifier, Request-Reply, Competing Consumers, Control Bus, Message Translator, Transactional Client, Process Manager, Recipient List, Message Store, Content-Based Router, Guaranteed Delivery, Message Expiration, Canonical Data Model, Channel Adapter, Command Message, Resequencer, Message Dispatcher and Event Message. The shelf, the home, the studied list and the `Study` facet count them with the two earlier works, sixty in all.
- **Flow drawings.** The new `flow` family draws endpoints as boxes and channels as pipes, a column per stage on a wide screen and a row per stage on a phone. A box holds its name, its state and the messages it holds; a message moving at the selected step is a green token on its line and the nodes it leaves or reaches are outlined in green; messages that cannot sit apart share a capsule and a line that skips a stage runs round the boxes. Every study opens at its start, and the text equivalent names each step's moves behind Show the messages.
- **Examples that run.** Eleven studies, the seven stream patterns among them, export a marble example and a flow routed over it; a spec beside each runs the example under the TestScheduler, the flow is built from the same object, and the reader can switch to the run's marble diagram at the same step. The nine that do not run say why.
- **Examples in the platform's own terms.** Each example is drawn from DotLn's or this app's public records and stated as an analogy that names and cites the record it reads; where the analogy breaks, the limits say so.
- **The record check and the rules.** The check holds a flow drawn over an executable example to its module; the catalog rules state the messaging rule and the analogy rule; the catalog architecture describes the family, the two builders and the coverage.

## Progressive polish

The worked step's rounding note shows only when the worked step shows a decimal number. The marble diagram's stylesheet carries only the three tones it draws. The study composite's fixtures and stories gain a flow case and a flow-that-runs case, and the Storybook browser check opens both. The catalog's sticky shelf and contents stop above the reading history, with a browser test at 768 and 1280 pixels. Two translation files gain the four keys.
