## Release overview

Patterns of Enterprise Application Architecture now has twenty studied concepts in the catalog, which brings the catalog to a hundred. Open Tools, then Catalog, and choose the work: each study gives the idea in plain words and the situation it serves in this app, a stepped drawing, ordinary pseudocode, the TypeScript model where one runs, public implementations, references, limits and nearby patterns. Each study names first the file in this app where the pattern, or a cousin of it, lives, offered as its author's reading of the code and never as a claim that the code was designed that way. A reader learns which of these patterns the app's stores and data access already carry, under what name, and where each one stops.

## Read before upgrading

The catalog loader no longer reads `tool-v0` checkpoints: a chunk in that schema is now refused as an unsupported shape, like any other. No release since v0.4.0 has shipped data in that schema, and v0.5.0 was the one compatibility release promised for it. Nothing else needs doing: no route, dependency, configuration, stored record or public interface changes. The new studies' text loads from a new message catalog, `i18n/studyPoeaa/en.json`, the first time the work is read.

## Substantive changes

**Twenty studies.** Data Mapper, Unit of Work, Identity Map, Identity Field, Foreign Key Mapping, Lazy Load, Record Set, Gateway, Service Stub, Registry, Plugin, Service Layer, Remote Facade, Data Transfer Object, Optimistic Offline Lock and Pessimistic Offline Lock each run a small in-memory TypeScript model of the mechanism, and the model's spec drives the study's own example; the drawing reads the same run. Domain Model, Transaction Script, Template View and Page Controller are structural choices with nothing to run, so they have no drawing and say why. Unit of Work steps three compositions through its new, dirty and removed registers to one commit; Identity Map shows a lookup that misses and one that hits; the two offline locks show where each fails; Data Transfer Object and Remote Facade say why they come as a pair.

**The states drawing.** A new drawing family shows a register: the example's states as columns and its objects as rows, with each object's token in the column of its state. Stepping moves the tokens: a moving token is green, with an arrow from the state it left and the operation that moved it, the column it enters is tinted, and an object that leaves the example leaves a dashed ring. The text equivalent names what moved and where every object stands, and sits behind Show the states. Under reduced motion a token is simply there, and nothing plays by itself. Below 600 pixels the register is drawn for a phone's width.

**Where the app carries each pattern.** Each study's first implementation is a file of this repository at the reviewed base commit, with the author's reading of where the pattern or its cousin shows and where it stops, followed by public implementations in Doctrine, Hibernate, MikroORM, TypeORM, Entity Framework, Spring, Rails and others. The developer reference's events-and-state document gains a section naming the patterns the stores and data access carry, each linked to its study.

**Study rules.** The study check now requires the states drawing of a study whose model runs to read that model's module, and holds the enterprise work's RxJS readings to the illustrative mark. The catalog's architecture and authoring rules describe the states family and say how a study names where the app embodies a pattern.

## Progressive polish

The flow and states drawings share their text wrapping in one module, and whole-number ticks on count charts come from one helper. Three visual baselines changed because the shelf now counts the work's twenty studies. Browser tests cover the work's studied list, Unit of Work's registers under reduced motion, Identity Map's miss and hit, both locks opened from the contents, and fit and accessibility at 360, 768 and 1440 pixels.

## Evidence and compatibility

Built on `v0.10.2` (`9637f73`) with no dependency, Node or Angular change. The registered review gate (install, lint, type check, unit tests, format, build, browser and visual tests) passed on the reviewed tree, after the final review corrected sixteen sentences in seven studies so that each agrees with its own run at every input and with the app's code. The initial bundle is 406,523 bytes, 38 more than at the base, with no lazy code in it; the twenty records load as one lazy chunk of 74,526 bytes, the states drawing loads with the Tools feature, and each model loads with its own study. An independent verification stepped the studies in a production build at 360, 768, 1440, 2080 by 1460 and 3840 by 1620 with no horizontal overflow or console error, and probed the sixteen models over 84 input combinations. All 75 addresses the studies cite answered 200 on 2026-11-07. Known limits: on a phone a state's name too wide for its column is drawn smaller, down to about 6.5 pixels for Service Layer's "Announced"; the register is the family's only drawing until a comparison with a state-machine drawing is run; tokens show one letter or digit rather than translated text; browser checks ran in Chromium only.
